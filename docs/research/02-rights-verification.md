# Rights & License Verification — কীভাবে আসলে কাজ করবে

> প্রশ্ন: "License field টা verify হবে কীভাবে?"
> সংক্ষিপ্ত উত্তর: সফটওয়্যার লাইসেন্সের *সত্যতা* প্রমাণ করতে পারে না।
> যা পারে — **গেট আটকানো, যাচাইযোগ্য অংশটুকু অটোমেট করা, আর অডিট ট্রেইল রাখা।**

---

## লেয়ার ১ — Structural validation (১০০% অটোমেটেড, নিজেরা কোড করব)

সবচেয়ে সস্তা লেয়ার, অথচ ৮০% ভুল এখানেই ধরা পড়ে। কোনো বিচারবুদ্ধি লাগে না, শুধু নিয়ম:

```ts
// ভিডিও PUBLISHED হওয়ার আগে অবশ্যই পাস করতে হবে
function canPublish(video: Video): Result {
  if (!video.licenseId)                 return fail("license নেই");
  if (!license.documentUrl)             return fail("চুক্তির ডকুমেন্ট আপলোড হয়নি");
  if (license.validUntil < now())       return fail("লাইসেন্সের মেয়াদ শেষ");
  if (license.grantor.status !== "APPROVED")
                                        return fail("grantor এখনো অনুমোদিত নয়");
  for (const p of video.performers) {
    if (!p.ageVerifiedAt)               return fail(`${p.slug}: বয়স যাচাই হয়নি`);
    if (!p.releaseSignedAt)             return fail(`${p.slug}: release form সই হয়নি`);
  }
  return ok();
}
```

সাথে কয়েকটা অটো-রুল:

- **Expiry cron** — প্রতিদিন রাতে চলবে, মেয়াদোত্তীর্ণ লাইসেন্সের ভিডিও নিজে থেকেই `UNPUBLISHED` হয়ে যাবে এবং sitemap থেকে বাদ পড়বে
- **Document hash** — আপলোড করা PDF/ছবির SHA-256 স্টোর করা হবে, পরে কেউ বদলালে ধরা পড়বে
- **Immutable audit log** — কে, কখন, কোন IP থেকে লাইসেন্স রেকর্ড যোগ/সম্পাদনা করল; append-only, ডিলিট করা যাবে না

## লেয়ার ২ — Identity verification (আসল verification, বাইরের API)

এই লেয়ারটাই সত্যিকারের "যাচাই", কারণ এখানে তৃতীয় পক্ষ সরকারি ID চেক করে।

### ২.১ পারফর্মারের বয়স ও পরিচয়
প্রোভাইডার: **Persona, Veriff, Jumio, Yoti** (যেকোনো একটা)

```
পারফর্মার → ID ডকুমেন্ট আপলোড + সেলফি (liveness check)
          → প্রোভাইডার সরকারি ডকুমেন্ট যাচাই করে, মুখ মেলায়
          → webhook আসে: { status: "approved", dob: "...", documentType: "..." }
          → আমরা শুধু ফলাফল + reference ID রাখব, ID-র ছবি রাখব না
```

এটা **চেকবক্স নয়, আসল যাচাই**। আর এটাই US 18 U.S.C. §2257-স্টাইল রেকর্ড-কিপিংয়ের মূল ভিত্তি — যেকোনো পেমেন্ট প্রসেসর (Visa/Mastercard) অ্যাডাল্ট সাইটে এটা বাধ্যতামূলক করে।

### ২.২ Release form-এ ই-স্বাক্ষর
প্রোভাইডার: **DocuSign / Dropbox Sign**

ফেরত আসে tamper-evident certificate — কে, কখন, কোন IP, কোন ইমেইল থেকে সই করেছে।
স্ক্যান করা কাগজের চেয়ে আইনি দিক থেকে অনেক শক্তিশালী।

Release form-এ আলাদা দুটো চেকবক্স থাকবে (মনে আছে, দুটো আলাদা অনুমতি):
- [ ] এই কনটেন্ট distribute করার অনুমতি
- [ ] আমার **নাম** ট্যাগ/পেজ হিসেবে ব্যবহারের অনুমতি → এটাই `nameUsageConsent`

### ২.৩ Grantor (স্টুডিও/পার্টনার) যাচাই
নতুন grantor onboard করার সময় একবার, ম্যানুয়ালি:

- কোম্পানি রেজিস্ট্রেশন নম্বর + সরকারি রেজিস্ট্রিতে যাচাই
- ডোমেইন মালিকানা প্রমাণ (DNS TXT রেকর্ড — আমরা একটা টোকেন দেব, ওরা বসাবে)
- অফিসিয়াল ডোমেইনের ইমেইল থেকে যোগাযোগ নিশ্চিতকরণ
- স্বাক্ষরিত master agreement, যাতে **indemnity clause** থাকবে
  ("রাইটস আমাদের, ভুল হলে দায় আমাদের")
- ব্যাংক/পেমেন্ট counterparty মিলিয়ে দেখা

`Grantor.status = APPROVED` না হওয়া পর্যন্ত ওদের কোনো ভিডিও publish হবে না।

## লেয়ার ৩ — Content matching (অটোমেটেড signal, reject নয় — flag)

লাইসেন্স কাগজে ঠিক থাকলেও ভিডিওটা চুরি হতে পারে। এই লেয়ার সেটা ধরার চেষ্টা করে:

| চেক | কীভাবে | কী ধরা পড়ে |
|---|---|---|
| Internal dedupe | ভিডিও ফ্রেমের pHash | একই ভিডিও দুইবার, দুই grantor থেকে |
| Thumbnail reverse search | Google Vision / TinEye API | ভিডিও আগে থেকেই ১০+ সাইটে আছে |
| Metadata inspection | ffprobe — এনকোডার ট্যাগ, তৈরির তারিখ | অন্য টিউবের re-encode signature |
| Known-infringement list | fingerprint সাবস্ক্রিপশন (যদি নিই) | পরিচিত পাইরেটেড ক্যাটালগ |

এগুলোর কোনোটাই অটো-reject করবে না — **`REVIEW` কিউতে পাঠাবে**। False positive প্রচুর হয়।

> বাস্তব কথা: thumbnail reverse search-এ যদি দেখা যায় ভিডিওটা ইতিমধ্যে ২০টা টিউবে আছে,
> grantor যতই কাগজ দেখাক — ওটা publish করা ঝুঁকিপূর্ণ।

## লেয়ার ৪ — Human review workflow

স্কেলে প্রতিটা ভিডিও মানুষ দেখতে পারবে না। তাই ঝুঁকি অনুযায়ী ভাগ:

```
নতুন Grantor      → ১০০% ম্যানুয়াল রিভিউ (একবারই, onboarding-এ)
নতুন Performer    → ১০০% ম্যানুয়াল রিভিউ (একবারই)
প্রথম ২০টা ভিডিও  → নতুন grantor-এর প্রতিটা দেখা হবে
তারপর             → ১০% র‍্যান্ডম spot-check
লেয়ার ৩ flag      → ১০০% রিভিউ
```

অ্যাডমিন প্যানেলে স্ট্যাটাস ফ্লো:

```
DRAFT → PENDING_REVIEW → APPROVED → PUBLISHED
                ↓
            REJECTED (কারণ লগ হবে)
```

## লেয়ার ৫ — Ongoing (লঞ্চের পর, কিন্তু দিন ১ থেকেই লাগবে)

- **DMCA / takedown endpoint** — পাবলিক ফর্ম, auto-ticket, ২৪–৪৮ ঘণ্টার SLA
- **Repeat-infringer policy** — একই grantor থেকে ৩টা valid takedown এলে পুরো ক্যাটালগ সাসপেন্ড
- **Content removal request** — পারফর্মার নিজে এসে নিজের কনটেন্ট সরাতে পারবেন, কারণ জিজ্ঞেস না করেই
- **বার্ষিক re-attestation** — grantor-কে প্রতি বছর নতুন করে নিশ্চিত করতে হবে রাইটস এখনো আছে
- **Takedown লগ** — সব রিকোয়েস্ট ও পদক্ষেপ সংরক্ষিত; এটাই "good faith operator" প্রমাণ

## খরচের বাস্তবতা

| আইটেম | আনুমানিক |
|---|---|
| ID verification | ~$1–2 প্রতি পারফর্মার (একবার) |
| E-signature | ~$0.5–2 প্রতি ডকুমেন্ট |
| Reverse image search | ~$1.5 প্রতি ১০০০ কল |
| মানুষের রিভিউ সময় | সবচেয়ে বড় খরচ |

**গুরুত্বপূর্ণ:** খরচটা পারফর্মার-প্রতি, ভিডিও-প্রতি নয়। ৫০ জন পারফর্মারের ১০,০০০ ভিডিও
হলে ID verification বাবদ মোট খরচ ~$১০০। নগণ্য।

## এক লাইনে সারকথা

সিস্টেম **প্রমাণ** করে না যে আপনার রাইটস আছে।
সিস্টেম **অসম্ভব করে তোলে** ডকুমেন্টেশন ছাড়া কিছু publish করা,
আর **প্রমাণযোগ্য করে তোলে** যে আপনি সদ্ভাবে কাজ করেছেন।

আইনি বিরোধে ঠিক এই দ্বিতীয় জিনিসটাই আপনাকে বাঁচায়।
